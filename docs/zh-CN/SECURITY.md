# 安全模型

[English](../SECURITY.md) | **简体中文** | [日本語](../ja-JP/SECURITY.md)

## 威胁模型

AutoDevOps Bridge 假设仓库内容、issue、pull request、工作流日志、服务日志和状态快照都可能包含恶意或误导性文本。它们属于数据，而不是可信指令。

主要风险包括提示注入、过大的 GitHub 权限、未经授权的工作流触发、secret 泄露、不受限制的生产 shell 访问、跨租户访问，以及数据库迁移场景下不安全的回滚。

## 控制措施

### 不提供不受限制的 shell

MCP 服务器不提供 `run_shell`、`ssh`、`exec` 或任意工作流名称工具。它只能调用服务器端项目注册表中保存的工作流文件名。

### GitHub 最小权限访问

私有 MVP 测试应使用仅限所选仓库的 GitHub fine-grained token。公开发布时，应以每用户 OAuth 和加密的租户范围存储替代共享 token。

### 脱敏状态边界

快照不得包含 `.env`、API 密钥、私钥、cookie、数据库连接字符串、完整用户文档、个人记忆内容或不受限制的原始日志。

### 写操作控制

- 部署只能触发白名单中的工作流。
- 诊断使用有界输入，并由目标工作流强制执行服务白名单。
- 回滚必须提供字面值 `ROLLBACK` 确认，并标记为破坏性操作。
- 生产工作流应使用并发锁以及可信分支或 SHA。

### 传输安全

- 公开模式必须位于 HTTPS 之后。
- 私有 HTTP MVP 支持 bearer secret 和 Host 白名单。
- 公开模式必须实现 OAuth 2.1、PKCE、audience/resource 验证、过期和撤销机制。

### 可审计性

所有生产操作都通过 GitHub Actions 工作流执行，从而保留操作者、提交、输入、时间戳、日志和结果。

## 运维建议

- 当常驻 Runner 具有生产访问权限时，保持受管仓库为私有。
- 使用专用非 root Runner 账户。
- 避免在生产 Runner 上运行不可信 fork PR。
- 保护生产工作流和项目注册表。
- 公开发布前，将第三方 actions 固定到经过审查的提交 SHA。
- 设置日志、备份和 Docker 镜像保留策略。
- 针对磁盘压力、重复重启、部署失败和状态快照过期设置告警。

## 事件响应

1. 在注册表中禁用或移除受影响项目。
2. 撤销 GitHub token 或 OAuth 授权。
3. 如果怀疑存在未经授权的调用，停止 MCP 服务。
4. 检查 GitHub 工作流历史。
5. 轮换可能已泄露的凭据。
6. 通过经过审查的回滚流程恢复可信版本。
7. 恢复访问前添加回归测试。
