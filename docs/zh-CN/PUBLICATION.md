# ChatGPT 发布检查清单

[English](../PUBLICATION.md) | **简体中文** | [日本語](../ja-JP/PUBLICATION.md)

此仓库包含技术插件包。要公开上架，仍需要由开发者账户所有者完成账户、身份、域名和政策相关操作。

## 技术准备情况

- [x] 独立的公开仓库。
- [x] `.codex-plugin/plugin.json` 中的插件清单。
- [x] `skills/` 下的可复用 Skill。
- [x] 支持 stdio 和 Streamable HTTP 的 MCP 服务器。
- [x] 明确的读取/写入/破坏性/开放世界工具注解。
- [x] 不提供任意 shell 或 SSH 工具。
- [x] 支持 HTTPS 部署的容器镜像。
- [ ] OAuth 2.1 授权服务器集成。
- [ ] 租户范围的加密 token 存储。
- [ ] 速率限制和滥用防护。
- [ ] 持久化审计数据库。
- [ ] 公开生产部署与监控。
- [ ] MCP 服务注册后配置远程 MCP 连接元数据。

## 上架素材

- [ ] 最终公开插件名称。
- [ ] 方形图标和 Logo 素材。
- [ ] 展示项目状态、部署、诊断和回滚确认的截图。
- [ ] 公开网站。
- [ ] 支持 URL/联系方式。
- [ ] 隐私政策。
- [ ] 服务条款。
- [ ] 数据保留和删除说明。

## 审核材料

- [ ] 解释 GitHub Runner 架构，以及为什么不收集 SSH 密钥。
- [ ] 提供演示/测试 GitHub 账户或审核仓库。
- [ ] 提供至少五个成功用户场景。
- [ ] 提供至少三个负面/错误场景。
- [ ] 记录每个 OAuth scope 及其必要性。
- [ ] 记录内容安全策略中的所有外部域名。
- [ ] 验证 MCP 域名和开发者身份。

## 建议的正向审核场景

1. 列出已注册的演示项目。
2. 读取健康项目的状态快照。
3. 读取最近的 CI 和部署运行记录。
4. 触发演示诊断工作流并观察已接受的结果。
5. 为已测试的 `main` 分支触发演示部署，随后验证已部署 SHA。

## 建议的负向审核场景

1. 请求未知项目 ID；工具返回有界错误，且不执行任何操作。
2. 未提供字面值 `ROLLBACK` 就请求回滚；schema 验证拒绝调用。
3. 尝试指定任意工作流或 shell 命令；不存在此类工具或参数。
4. 使用已过期或已撤销的 OAuth token；服务器拒绝访问。
5. 请求用户无权访问的仓库状态；服务器拒绝访问。

## 发布顺序

1. 针对 SuMeMe 完成私有端到端测试。
2. 在经过验证的公开域名下部署支持 OAuth 的 MCP 服务。
3. 创建生产政策和支持页面。
4. 在 ChatGPT 中注册并测试远程 MCP 连接。
5. 准备截图和审核人员测试凭据。
6. 通过 OpenAI 插件/应用提交流程提交。
7. 在不削弱安全模型的前提下处理审核反馈。

## 需要开发者账户所有者完成的操作

- 接受平台条款；
- 完成身份或企业验证；
- 证明对公开域名的控制权；
- 授权 OAuth 应用；
- 提交法律声明；
- 在需要时执行最终公开提交操作。
