## 推奨される正常系審査シナリオ

1. 登録済みデモプロジェクトを一覧表示する。
2. 正常なプロジェクトのステータススナップショットを読み取る。
3. 最近の CI とデプロイ実行を読み取る。
4. デモ診断ワークフローを起動し、受理された結果を確認する。
5. テスト済み `main` ブランチのデモデプロイを起動し、その後デプロイ済み SHA を検証する。

## 推奨される異常系審査シナリオ

1. 不明なプロジェクト ID を要求する。ツールは制限付きエラーを返し、操作を実行しない。
2. 文字列 `ROLLBACK` なしでロールバックを要求する。schema 検証が呼び出しを拒否する。
3. 任意のワークフローまたは shell コマンドを指定しようとする。そのようなツールやパラメータは存在しない。
4. 期限切れまたは失効済み OAuth token を使用する。サーバーがアクセスを拒否する。
5. ユーザーの認可外リポジトリの状態を要求する。サーバーがアクセスを拒否する。

## 公開手順

1. SuMeMe に対する非公開エンドツーエンドテストを完了する。
2. 検証済み公開ドメインで OAuth 対応 MCP サービスをデプロイする。
3. 本番ポリシーとサポートページを作成する。
4. ChatGPT でリモート MCP 接続を登録してテストする。
5. スクリーンショットと審査用テスト認証情報を用意する。
6. OpenAI のプラグイン/アプリ提出プロセスから申請する。
7. セキュリティモデルを弱めずに審査フィードバックへ対応する。

## 開発者アカウント所有者が行う必要のある操作

- プラットフォーム規約への同意。
- 本人または事業者確認。
- 公開ドメインの管理権限証明。
- OAuth アプリケーションの承認。
- 法的表明の提出。
- 必要な場合の最終公開提出操作。
