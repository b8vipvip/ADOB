# ADOB 本番準備チェックリスト

[English](../PUBLICATION.md) | [简体中文](../zh-CN/PUBLICATION.md) | **日本語**

ADOB は自動開発エージェントシステムです。この文書はプライベートまたはマルチユーザー運用の本番準備を確認します。

## コントローラー

- [x] 制限 MCP ツールと操作注釈。
- [x] プロジェクト許可リストと VSR/GHS。
- [x] 任意 Shell/SSH ツールなし。
- [x] Streamable HTTP / stdio。
- [x] プライベート HTTP 認証。
- [x] キュー、実行中、終端の正しい判定。
- [x] 最大 5 分待機と後からの再確認。
- [ ] 公開マルチユーザー向け OAuth 2.1 / PKCE。
- [ ] テナント分離された暗号化資格情報。
- [ ] レート制限、悪用防止、失効。
- [ ] 永続監査と保持ポリシー。

## GitHub

- [x] Fine-grained Token 権限ガイド。
- [x] 管理リポジトリ導入ウィザード。
- [x] CI、デプロイ、診断、ロールバック、状態テンプレート。
- [x] 再利用 Workflow の固定。
- [x] GHS の SSH ホスト鍵固定。
- [ ] 全リポジトリの Branch protection / Ruleset。
- [ ] Token 更新計画。
- [ ] VSR Runner 更新・分離手順。

## VPS

- [x] GHS の非 root アカウント。
- [x] 本番データをソース同期から除外。
- [x] 限定診断と明示ロールバック確認。
- [ ] 検証済みバックアップ・復元。
- [ ] ディスク、メモリ、ヘルス、証明書監視。
- [ ] インシデント対応と緊急アクセス。
- [ ] サーバー交換後の復旧テスト。

## Workflow テスト

- [ ] キュー中を pending とし失敗にしない。
- [ ] 実行中を非終端として扱う。
- [ ] `wait_seconds=0` が追跡情報を返す。
- [ ] 300 秒以内の完了を正しく判定する。
- [ ] 300 秒超過時に継続中を返す。
- [ ] GitHub の終端 conclusion 後だけ失敗とする。
- [ ] 実行中に重複デプロイしない。
- [ ] デプロイ完了後に本番検証する。

## リリース順序

1. 型チェック、単体テスト、コンテナビルド。
2. 可能なら GHS と VSR を各一件テスト。
3. pending、成功、失敗、タイムアウトを検証。
4. サニタイズ済み `ops-status` を確認。
5. Secrets、Token 権限、ホスト鍵を確認。
6. リリースタグを作成し管理プロジェクトから固定参照。
7. 初回本番 Run とデプロイ SHA を監視。
