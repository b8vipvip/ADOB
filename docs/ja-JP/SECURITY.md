# セキュリティモデル

[English](../SECURITY.md) | [简体中文](../zh-CN/SECURITY.md) | **日本語**

## 脅威モデル

AutoDevOps Bridge は、リポジトリ内容、issue、pull request、ワークフローログ、サービスログ、ステータススナップショットに悪意のある、または誤解を招くテキストが含まれる可能性を前提とします。これらはデータであり、信頼済み命令ではありません。

主なリスクには、プロンプトインジェクション、過剰な GitHub 権限、未承認のワークフロー起動、secret 漏えい、無制限の本番 shell アクセス、テナント間アクセス、データベース移行を伴う危険なロールバックが含まれます。

## 制御策

### 無制限 shell を提供しない

MCP サーバーには `run_shell`、`ssh`、`exec`、任意のワークフロー名を指定するツールはありません。サーバー側プロジェクトレジストリに保存されたワークフローファイル名のみを呼び出せます。

### 最小権限の GitHub アクセス

非公開 MVP テストでは、選択したリポジトリだけに制限した GitHub fine-grained token を使用します。公開版では共有 token を廃止し、ユーザー単位 OAuth と暗号化されたテナントスコープのストレージに置き換えます。

### サニタイズ済みステータス境界

スナップショットには `.env`、API キー、秘密鍵、cookie、データベース接続文字列、完全なユーザー文書、個人メモリ内容、無制限の生ログを含めてはいけません。

### 書き込み操作の制御

- デプロイは許可リスト内ワークフローのみを起動する。
- 診断は制限付き入力を使用し、対象ワークフローがサービス許可リストを強制する。
- ロールバックには文字列 `ROLLBACK` の確認が必要で、破壊的操作として示す。
- 本番ワークフローは同時実行ロックと信頼済みブランチまたは SHA を使用する。

### トランスポートセキュリティ

- 公開モードは HTTPS の背後で動作させる。
- 非公開 HTTP MVP は bearer secret と Host 許可リストに対応する。
- 公開モードでは OAuth 2.1、PKCE、audience/resource 検証、有効期限、失効を実装する。

### 監査可能性

すべての本番操作を GitHub Actions ワークフローとして実行し、実行者、コミット、入力、タイムスタンプ、ログ、結果を保持します。

## 運用上の推奨事項

- 常駐 Runner が本番アクセスを持つ場合、管理対象リポジトリを非公開にする。
- 専用の非 root Runner アカウントを使用する。
- 本番 Runner 上で信頼できない fork PR を実行しない。
- 本番ワークフローとプロジェクトレジストリを保護する。
- 公開前にサードパーティ actions をレビュー済みコミット SHA へ固定する。
- ログ、バックアップ、Docker イメージの保持ポリシーを設定する。
- ディスク逼迫、繰り返し再起動、デプロイ失敗、古いスナップショットを通知する。

## インシデント対応

1. 影響を受けたプロジェクトをレジストリで無効化または削除する。
2. GitHub token または OAuth grant を失効させる。
3. 未承認呼び出しが疑われる場合は MCP サービスを停止する。
4. GitHub ワークフロー履歴を確認する。
5. 漏えいした可能性のある認証情報をローテーションする。
6. レビュー済みロールバック手順で信頼できるリリースを復元する。
7. アクセスを復旧する前に回帰テストを追加する。
